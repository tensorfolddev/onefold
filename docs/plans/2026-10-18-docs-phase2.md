# Docs Phase 2 (Connected docs) — Implementation Plan

> Use superpowers:executing-plans. Spec: `docs/specs/2026-10-18-docs-design.md` §8 (and §10 for MCP). The global
> constraints of the phase 1 plan apply unchanged.

**Goal:** Docs that connect: @mentions that notify, live ticket and doc chips, backlinks, link-preview cards, quick
link editing, and docs in the header search.

**Architecture:**
- **Three inline or block nodes, shared by the editor and Markdown.** `mention` → `[@Name](mention:<personId>)`.
  `ref` → `[EN-12](ticket:EN-12)` or `[Title](doc:<id>)`. `linkCard` → a line holding only `<https://…>`.
  - Each has its own Markdown tokenizer, so plain links stay plain.
  - In the browser, they render through React node views that read live store data (status, assignees, titles).
- **On every save, the server rebuilds a `doc_links` index** from the body. New `mention:` targets become
  notifications, through a server-only command. The index answers "Linked from" for docs and "Mentioned in docs" for
  tickets.
- **Link previews** come from `GET /api/docs/unfurl` (SSRF-guarded fetch plus a `link_previews` cache).

---

### Task 1: Nodes and their Markdown
- **Create:**
  - `src/features/docs/editor/nodes.ts`: `Mention`, `Ref` (attrs `kind: "ticket"|"doc"`, `id`, `label`) and
    `LinkCard` (attr `url`). Each has `markdownTokenizer`, `parseMarkdown`, `renderMarkdown` and a plain `renderHTML`.
  - `refsIn(markdown) → { people: string[]; tickets: string[]; docs: string[] }`, a pure scan used by the server.
- **Modify:** `extensions.ts` to add the three nodes.
- **Test (`markdown.test.ts`):**
  - Mention, ticket ref, doc ref and link card each round-trip exactly.
  - `[text](https://x)` stays a link mark.
  - `refsIn` finds all three kinds and ignores code blocks.

### Task 2: Editor pickers and live chips
- **Create:** `editor/Chips.tsx`, React node views:
  - The person chip shows an avatar and name.
  - The ticket chip shows the type icon, key, title, a status dot and an assignee. It opens the ticket panel.
  - The doc chip shows the icon and title, and links to the doc.
  - A target that's missing or not visible shows its label as plain text.
- **Create:** `editor/LinkCardView.tsx`. It fetches `/api/docs/unfurl` and shows the site icon, title, description,
  image and domain. Its toolbar offers "Show as link" and "Remove".
- **Create:** `editor/Pickers.tsx`, suggestion menus. `@` lists people who can see the doc. `[[` lists tickets and
  docs. Both reuse the slash menu's list UI.
- **Input rules and paste handling:**
  - A ticket key followed by a space becomes a chip when the ticket exists.
  - Pasting an app URL (`/t/KEY`, `/d/<id>`, `/docs/<id>`) gives a chip.
  - Pasting a bare `http(s)` URL into an empty paragraph gives a link card. Anywhere else, it gives a link.
- **Cmd/Ctrl+K** opens the selection toolbar's link editor.
- **Modify:** `DocEditor.tsx` to accept `people`, `findTicket`, `findDoc` and `onOpenTicket` through extension
  options.

### Task 3: Server — link index, mention notifications, backlinks, MCP
- **Migration `0010_doc_links`:** `doc_links(org_id, doc_id, kind, target)`, primary key on all four, an index on
  `(org_id, kind, target)`, RLS, and a cascade FK to docs. Plus `link_previews(url_hash pk, url, data jsonb,
  fetched_at)`, a platform table with no RLS.
- **Domain:** add the server-only command `notifyDocMentions(db, me, docId, personIds)`. It adds `mention`
  notifications ("mentioned you in <title>", target `/d/<id>`) for people who can see the doc, never yourself.
- **`server/docs.ts`:**
  - `saveBody` and `createDoc` rebuild `doc_links`. New person targets, compared with the old index, are sent through
    `applyComposed` as `notifyDocMentions`.
  - `readDoc` returns `backlinks: { id, title, icon, productKey }[]`, limited to docs visible to the viewer.
  - `docsLinkingTicket(who, key)` → `/api/docs/linked?ticket=KEY`.
- **MCP:**
  - `create_doc` and `update_doc` turn `[@x](mention:<email|name>)` into person ids, using `normalizeMentions`.
  - `get_doc` gains `backlinks`.
- **Tests (`docs.test.ts`):**
  - Mentioning Sam notifies Sam once. Saving again doesn't notify again. Mentioning yourself never notifies.
  - Someone who can't see the doc isn't notified.
  - Backlinks list only visible docs.
  - Linked docs come back for a ticket.

### Task 4: Link previews
- **Create:** `src/server/unfurl.ts`:
  - `unfurl(url)` takes http(s) only.
  - `assertPublic(host)` resolves DNS and refuses private, loopback, link-local, CGNAT, multicast and unspecified
    addresses, for IPv4 and IPv6 (including IPv4-mapped).
  - It follows at most 3 redirects, re-checking each. Limits: 5 s timeout, 1 MB, `text/html` only.
  - It parses `og:title`, `og:description`, `og:image`, `og:site_name`, `<title>` and the icon, and makes their URLs
    absolute.
  - Results are cached for 7 days. Rate limit: 30 a minute per person.
- **Create:** `src/app/api/docs/unfurl/route.ts`.
- **Test (`unfurl.test.ts`):**
  - The address checks.
  - Parsing a sample HTML page.
  - A local HTTP server is refused for being on loopback.

### Task 5: Screens
- **Doc footer:** "Linked from", backlinks as chips.
- **Ticket panel:** a "Mentioned in docs" section, shown when there are any.
- **Header search:** a dropdown that shows matching tickets (local) and docs (`searchDocs`, debounced). Enter opens
  the first result.
- **Styles** in `docs.css` for the chips, the link card and the picker.

### Task 6: e2e and finish
- **e2e:**
  - Typing `@Sid` in a company doc notifies Sid.
  - A ticket key followed by a space becomes a chip that opens the ticket panel.
  - A backlink appears on the linked doc.
- Run the full suite. Open a PR into `dev`, squash-merge once green, and verify the merge landed.
