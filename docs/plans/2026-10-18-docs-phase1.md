# Docs Phase 1 (Docs core) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn docs from a title and a kind into real pages: a Notion-style editor, project and company spaces,
nesting, autosave with live refresh and conflict safety, templates, search, admin-only archive and delete, and MCP
tools.

**Architecture:**
- Doc metadata stays in the company data every browser already has. It's changed by pure domain commands, so it
  gets the audit log and live refresh for free.
- Bodies (Markdown) and versions live in their own tables, behind `/api/docs`. They're loaded when a doc opens and
  saved with an optimistic `baseRev` check.
- Live body updates and presence ride the existing SSE stream as new event types.
- The editor is TipTap 3, loaded only on doc pages.

**Tech stack:** Next.js 16 App Router, React 19, Postgres + Drizzle, TipTap 3 (`@tiptap/*`, `@tiptap/markdown`),
lowlight, dnd-kit (already installed), emojibase-data (already installed), Playwright.

**Spec:** `docs/specs/2026-10-18-docs-design.md` (phase 1 = §11.1).

## Global constraints

- §12 rules: additive migrations only (CI rejects DROP/RENAME/SET NOT NULL), commands only gain optional
  arguments, MCP tools are additive and never include a delete tool.
- Permissions:
  - Everyone who can see a space creates and edits.
  - **Only admins** archive, restore and delete.
  - Deleting needs `Delete <title>` typed, and the doc must be archived first.
- Project docs are visible to people on the project and to admins. Company docs are visible to every active person.
  Archived docs are visible to admins only.
- Markdown is the stored format. No raw HTML is ever rendered. Links are limited to `http:`, `https:`, `mailto:` and
  `/api/files/`.
- New packages are pinned to an exact version **at least 14 days old** (the newest `@tiptap` release from on or
  before 2026-10-04).
- Commits: `Tensorfold <tensorfold@gmail.com>`, with no co-author lines. One PR into `dev`, squash-merged once CI is
  green.

## Deviations from the spec (found while reading the code)

- **Company space:** `docs.product_id` has an FK to `products`, so company docs store **NULL** (made nullable with
  `ALTER COLUMN … DROP NOT NULL`, which is allowed). The domain uses `productKey: ""`.
- **Sibling order:** the order is the docs list order (the table is `POSITIONED`), so there's no `position` field on
  `Doc`.

### Task 4: Server: create, read, save (with conflicts), search, presence, live events

**Files:**
- Create: `src/server/docs.ts`:
  - `createDoc(who, input & { body?: string }) → { version, id }`: in one transaction, load the company, run the
    `createDoc` command, save, insert a `doc_bodies` row with the template body when there's no body given, write
    version 1, and journal it.
  - `readDoc(who, id) → { doc, body, rev, presence }`: checks visibility against the snapshot.
  - `saveBody(who, id, { body, baseRev, force?: boolean }) → { rev }`:
    - Row lock. Requires `doc.edit`.
    - If `baseRev !== rev` and there's no `force`, throw `DocConflict(latest)`.
    - Otherwise store the body and `rev+1`, and update the coalesced version (same author within 10 min) or insert a
      new one. A forced save snapshots the version it overwrites first.
    - Run `touchDoc` through the company at most once per 2 minutes per doc (it's skipped when the last meta
      `updatedAt` is less than 2 minutes old).
    - `pg_notify(CHANNEL, \`${org}:doc:${id}:${rev}:${personId}\`)`.
  - `searchDocs(who, q) → { id, title, snippet }[]`: `websearch_to_tsquery('simple', q)` on bodies, plus title
    `ILIKE`, limited to visible docs, at most 20.
  - `setPresence(who, id, editing)` and `presenceOf(orgId, id)`: an in-memory map with a 40 s TTL that notifies
    `${org}:presence:${id}`. `ponytail:` it's per process.
  - Export `class DocConflict extends Error { latest }`.
- Modify: `src/server/events.ts`. The listener gets the raw payload. `subscribe` callbacks receive
  `{ type: "version", version } | { type: "doc", docId, rev, personId } | { type: "presence", docId }`.
- Modify: `src/app/api/org/[action]/route.ts` so the SSE stream writes `event: doc` and `event: presence` too.
- Create these routes, each through `handle` and `requireSession`:
  - `src/app/api/docs/route.ts`: `POST` creates.
  - `src/app/api/docs/[id]/route.ts`: `GET` and `PUT`. A conflict returns **409** `{ latest }`.
  - `src/app/api/docs/[id]/presence/route.ts`: `POST { editing }` returns `{ presence }`.
  - `src/app/api/docs/search/route.ts`: `GET ?q=`.
- Test: `src/server/docs.test.ts`, on a real Postgres via `freshDatabase`.

- [ ] Write the tests:
  - Create from a template has a body.
  - A developer off the project can't read the doc (AccessError).
  - `saveBody` with a stale `baseRev` throws `DocConflict` with the latest body.
  - `force` overwrites and keeps a version of what it replaced.
  - Two saves within 10 minutes leave one version.
  - Meta `updatedAt` is set by the first save, and not re-set by a second save 1 s later.
  - Search finds a word from the body, and not in a doc the searcher can't see.
- [ ] Implement until `node --test src/server/docs.test.ts` passes. Then run the full `npm test`.
- [ ] Commit: `feat: docs API — create, read, autosave with conflict check, search, presence, live doc events`
